# GDD v1 — «Лавка алхимика» (рабочее название)

Статус: **v1.0** (2026-10-24, подэтап S0.5).
Все числа — **стартовые значения** (Numbers Policy): тест, критерий и «что делать, если провал» — в §12. В код они попадают только через ресурсы (`EconomyConfig`, `.tres`).
Названия ингредиентов, рецептов и фразы — черновые. Перед попаданием в `localization/strings.csv` проходят humanizer (S1.7).
Продолжение документа: `docs/gdd/STATIONS.md` — машины состояний, juice, краевые случаи, 5-компонентная оценка, плейтесты, допущения.

## 1. Коротко
- **Жанр:** казуальный симулятор алхимической лавки (гибридно-казуальный). Яндекс Игры, ПК и телефон, ru/en.
- **Фантазия игрока:** «я учёный-алхимик и разбираюсь в веществах лучше всех в городе».
- **Глаголы:** принять заказ → выбрать ингредиенты → растолочь → разделить (отстоять, выпарить) → отдать → улучшить лавку → открыть рецепт.
- **Ритм:** заказ 30–60 с; игровой день = 6 заказов ≈ 3–6 мин; контент MVP до 5-го ранга ≈ 75 мин плюс коллекция «золотых» страниц.
- **Темп спокойный:** таймеров ожидания нет. Ошибка стоит только ингредиентов и времени.

## 2. Основной цикл

````
Клиент → заказ иконками → полка → Ступка → [Отстойник] → [Горелка] → Клиент
   ↑                                                                  ↓
   └── магазин: станции, приборы, ингредиенты ← монеты · репутация · Гримуар
````

| Момент | Что получает игрок |
|---|---|
| 0–30 с | первый заказ, первые монеты, первая страница Гримуара |
| ~2–3 мин | покупка Отстойника — новое действие |
| ~5 мин | итог первого дня, 3+ рецепта, ранг 2 рядом |
| ~15 мин | ранг 3: Горелка, термометр |
| ~40 мин | ранг 4: Росток-проверяльщик, тройные рецепты |
| ~75 мин | ранг 5: королевские заказы, охота за «золотыми» страницами |

## 3. Алхимическая модель

### 3.1 Шесть свойств

| id | Название | Цвет | Узор в слое | Плотность (1 — дно) | Нагрев | Зачем нужно |
|---|---|---|---|---|---|---|
| `acid` | Едкость | `#9B5DE5` | мелкие пузырьки | 1 | испаряется ≥ 75° | чистит, снимает ржавчину |
| `heat` | Жар | `#FF6B2C` | волнистые линии | 2 | стойкое | греет |
| `life` | Жизнь | `#7ED957` | листики | 3 | **разрушается ≥ 90°** | лечит |
| `cold` | Холод | `#5BC8F5` | снежинки | 4 | испаряется ≥ 35° | охлаждает |
| `sleep` | Сон | `#6C7BD9` | полумесяцы | 5 | испаряется ≥ 55° | успокаивает |
| `light` | Свет | `#FFE066` | искорки | 6 | стойкое | светится, бодрит |

- **Изменение относительно анализа:** «Яд» → «Едкость». Так мягче для 0+/6+, и появляются заказы кузнеца (ржавчина, флюс, полироль).
- Правила считываются без текста: тяжёлое внизу, лёгкое сверху; холод улетает первым; жизнь боится перегрева; жар и свет стойкие.
- **Цвет никогда не работает в одиночку:** у каждого слоя свой узор и плавающая иконка свойства (для дальтоников и маленьких экранов).

### 3.2 Смесь
- Смесь — это количество каждого свойства в **долях** (дробное число).
- Свойство **есть**, если его ≥ 0,3 доли (порог значимости). Меньше — **след**: на эффект не влияет, но снижает чистоту.
- **Сила** свойства = его доли. ★ ≥ 1,0 · ★★ ≥ 2,0 · ★★★ ≥ 3,0.
- **Чистота** = доли нужных свойств / доли всех свойств. ★ ≥ 60 % · ★★ ≥ 80 % · ★★★ ≥ 95 %.
- Вода — только среда, в расчётах не участвует.

### 3.3 Станции

**Ступка** (есть с начала). Вмещает 2 ингредиента (3 после улучшения).
- Круговой жест над чашей заполняет шкалу помола `p` от 0 до 1. Альтернатива для доступности — тапы: 1 тап = ¼ круга.
- Прирост за круг: мягкие +0,12, средние +0,09, твёрдые +0,07. В смеси считается самый твёрдый ингредиент.
- Доля извлечения:
  - `p < 0,70` → `0,4 + 0,6 · p / 0,70`;
  - `0,70…0,85` → **1,0 («идеально»)**;
  - `p > 0,85` → `1,0 − 2 · (p − 0,85)`, при `p = 1` это 0,7 (порошок пылит).
- Свойства смеси = доли ингредиентов × доля извлечения.

**Отстойник + Приёмник** (покупка, ранг 1).
- Принесённое содержимое смешивается с водой и за 1,2 с расслаивается (тап — пропустить).
- Слои лежат по плотности. Толщина пропорциональна долям, но не меньше 10 % высоты колбы: тонкий слой всё равно видно и можно поймать.
- Удержание наклоняет колбу: верхние слои стекают в Приёмник. Скорость: первые 0,5 с — 15 % высоты в секунду, дальше 30 %. Отпустил — струя прекращается за 0,1 с.
- В Приёмник переходит часть слоя, пропорциональная слитой высоте.
- Приёмник можно вылить отдельно. Дальше можно нести **любой** из двух сосудов: верх (Приёмник) или низ (Отстойник).

**Горелка** (покупка, ранг 3).
- Удержание раздувает огонь: температура растёт на 20°/с. Отпустил — падает на 12°/с до 20°. Максимум 100°.
- Пока температура не ниже точки свойства, оно уходит **паром своего цвета** со скоростью 1,2 доли/с.
- При ≥ 90° Жизнь сгорает со скоростью 0,8 доли/с: бурый дым, термометр дрожит.
- Жар и Свет не уходят никогда.

**Перенос.** Содержимое станции перетаскивается на другую станцию или клиенту. Альтернатива одной рукой: тап по сосуду → подсвечиваются допустимые цели → тап по цели.
- Станции проходятся в любом порядке и любое число раз.
- Ступка → Отстойник/Горелка: порошок сам ссыпается в колбу с водой.
- У каждой станции есть корзина «вылить». Нерастолчённые ингредиенты при этом возвращаются на полку бесплатно, остальное пропадает.
- Отданное прямо из ступки становится баночкой мази, из колбы — флаконом. Это только внешний вид, на оценку не влияет.

### 3.4 Что можно выделить
- Отстойник отрезает **верх или низ** по порядку плотности.
- Горелка снимает летучие **по возрастанию температуры**: {Холод} → {Холод, Сон} → {Холод, Сон, Едкость}.
- Нужны обе станции: Холод нагревом не выделить (он уходит первым), а убрать Едкость и сохранить Сон нагревом нельзя — только отстаиванием.

### 3.5 Рецепты и Гримуар
- Рецепт — это набор значимых свойств готового зелья (§5.1).
- Открытие засчитывается, когда зелье отдают клиенту (даже если он отказался) или проверяют Ростком.
- Страница Гримуара: название, иконки свойств, лучший результат, число варок. После 3 «безупречных» варок (§5.3) страница становится **золотой** — долгая цель коллекционера.
- Набор без рецепта — «Странная смесь», страницы у неё нет.

### 5.2 Заказ
Заказ = нужные свойства + требование к силе (★–★★★) + требование к чистоте (★–★★★).
В пузыре только иконки: каждое нужное свойство показано столько раз, сколько звёзд силы требуется; чистота — кристалл с 1–3 гранями. Фраза клиента — для атмосферы, а не инструкция.

### 5.3 Оценка: три звезды — три смысла

| Звезда | За что |
|---|---|
| ★ Эффект | все нужные свойства есть |
| ★ Сила | каждое нужное свойство не слабее требования |
| ★ Чистота | чистота не ниже требования |

- **Неверный эффект:** клиент вежливо отказывается, зелье пропадает, клиент продолжает ждать (можно переделать). Звёзды «Сила» и «Чистота» засчитываются только при верном эффекте.
- **«Безупречно»:** сила ★★★ по всем нужным свойствам и чистота ≥ 95 %. Даёт +20 % чаевых, +1 репутации и идёт в счёт «золотой» страницы.
- **Оплата** = база × {1★: 0,4 · 2★: 0,75 · 3★: 1,0} × (1 + чаевые). Чаевые: «безупречно» +0,20; серия 3★ подряд +0,05 за каждый заказ, максимум +0,25.
- **Репутация** = число звёзд + 1 за «безупречно». Репутацию не отнимаем никогда.
- **Формула базы** для составления заказов: `10 + 15 · n · S + 10 · P` (n — число свойств, S — звёзды силы, P — звёзды чистоты). Примеры: одно свойство ★/★ = 35; пара ★★/★★ = 90; тройка ★★★/★★★ = 175.

### 5.4 Генератор заказов
- Берёт шаблоны (`OrderTemplate`) по рангу и весам и выдаёт только те, что решаются уже открытыми ингредиентами и станциями. Проверка перебором на стенде S3.3.
- Один и тот же шаблон два раза подряд не выпадает.
- Текущий заказ хранится в сохранении (клиент + шаблон), так что перезагрузка его не меняет.

## 7. Прогрессия

**Ранги** (репутация): 1 Ученик — 0 · 2 Травник — 15 · 3 Алхимик — 50 · 4 Мастер — 120 · 5 Магистр — 250.

| Покупка | Тип | Ранг | Цена | Что даёт |
|---|---|---|---|---|
| Отстойник + Приёмник | станция | 1 | 90 | разделение по плотности |
| Индикаторная бумага | прибор знания | 2 | 180 | точные доли и чистота смеси на любой станции, отметки порогов ★ |
| Горелка | станция | 3 | 350 | разделение нагревом |
| Термометр с делениями | прибор знания | 3 | 250 | метки точек испарения для свойств, которые есть в смеси |
| Третье место в ступке | улучшение | 3 | 200 | тройные смеси, ★★★ проще |
| Росток-проверяльщик | прибор знания | 4 | 500 | показывает будущие звёзды до передачи, засчитывает открытие |
| Ингредиенты | открытие | 2–4 | §4 | новые свойства и пути |

- Без приборов игра проходится полностью: слои и цвет пара видны всегда. Приборы превращают догадку в точное знание — «жажда знаний» как механика.
- **Росток-проверяльщик** — милый росток в горшке с лицом. Реагирует на свойства смеси: Жизнь — цветёт, Холод — смешно дрожит в инее, Жар — краснеет, Сон — зевает и засыпает, Свет — светится, Едкость — морщится и чихает пузырьками. Ростку никогда не больно (Яндекс 3.4.3).

## 8. День, удержание, монетизация
- **Игровой день** = 6 заказов → итог дня: выручка, репутация, открытия, кнопка «Удвоить выручку (реклама)», затем предложение магазина (если что-то по карману).
- **Ежедневная награда** (реальные сутки, время сервера SDK), 7 дней: 40 · 60 · кристалл · 100 · 150 · 2 кристалла · 300. Пропущенный день цепочку не обнуляет: она просто ждёт. После 7-го дня цепочка начинается заново (стартовое решение, `DailyRewardConfig.restart_after_last`; проверка — удержание D7+ на S8).
- **Реклама за награду** (всегда по выбору игрока, кнопка помечена значком рекламы): удвоить выручку дня; подсказка к заказу (1 бесплатно в сутки, дальше за рекламу); вернуть ингредиенты после неверного эффекта (если они были платными); «подарок торговца» — 1 кристалл в сутки (ранг 4+). Частоту показов rewarded Яндекс не ограничивает (источник: yandex.ru/dev/games/doc/ru/sdk/sdk-adv).
- **Полноэкранная реклама** — только по кнопке «Следующий день» после итога и не в первые 2 игровых дня. Частотой полноэкранной рекламы управляет платформа; вызывать её во время активной игры нельзя — это считается фродом (источник: yandex.ru/dev/games/doc/ru/sdk/sdk-adv).
- **Стики-баннер** в MVP выключен (решаем на S10 после проверки раскладки).
- **Покупки за деньги** — после релиза.
- **Подсказка** берётся из `RecipeData.hint_steps` подходящего рецепта, например: «Огнецвет → Ступка → Отстойник: неси верх».

## 10. Экран и управление
- **Ландшафт (ПК):** слева полка (сетка), в центре станции в ряд на прилавке, справа клиент и пузырь заказа. HUD: монеты (слева вверху), репутация и ранг (по центру), Гримуар, магазин, настройки (справа).
- **Портрет (телефон):** верхние 35 % — клиент и заказ; средние 40 % — станции; нижние 25 % — полка-лента. Лента прокручивается внутри себя, сам экран не прокручивается (Яндекс 1.10).
- Цели касания — не меньше 96×96 px при базовом 1920×1080.
- Всё делается одной рукой: перетаскиванием или тапом по сосуду и тапом по цели.
- Иерархия: заказ и активная станция видны всегда; монеты и репутация привлекают внимание только при изменении; Гримуар и магазин открываются по запросу.
- Над порошком в ступке висят иконки свойств: смешанный цвет порошка сам по себе плохо читается.

## 11. Сохранение
- Пишем одной атомарной записью сразу после: передачи зелья, покупки, награды, смены дня, изменения настроек (Яндекс 1.9).
- **Сохраняем:** монеты, репутацию, ранг, покупки, открытые ингредиенты, Гримуар (открытия, лучшие результаты, счётчики «безупречно»), день и номер заказа в дне, серию 3★, текущий заказ, шаг FTUE, ежедневную награду (день цепочки, дата), флаги бесплатных подсказок и подарков, настройки.
- **Не сохраняем:** содержимое станций. После перезагрузки тот же клиент приходит с тем же заказом, станции пусты.

## 13. Данные → ресурсы (сделано на S1.6)
Классы — `data/<вид>/*.gd`, данные — `.tres` рядом; все вместе собраны в `data/catalog.tres` (`DataCatalog`, сцены получают его через `@export`). Источник правды — `.tres` (правятся в редакторе). `tools/data/bootstrap_gdd_v1.py` один раз выгрузил GDD v1 и не перезаписывает файлы; `--check` проверяет решаемость заказов упрощённым перебором. В Godot данные проверяет `scenes/debug/data_check.tscn`.
- `PropertyData` (`data/properties/`): id, name_key, color, icon, pattern (enum: пузыри, волны, листья, снежинки, луны, искры — рисует шейдер), density_rank, evaporate_temp, burn_temp (−1 — никогда).
- `IngredientData` (`data/ingredients/`): id, name_key, texture, properties (`Dictionary[StringName, float]`), hardness (enum), cost_per_use, unlock_rank, unlock_price, is_rare.
- `RecipeData` (`data/recipes/`): id, name_key, desc_key, property_set, tier, hint_steps. Подсказка — id ингредиентов и шаги станций (`mortar`, `settler_top`, `settler_bottom`, `burner_35_54`, `burner_55_74`, `burner_75_89`); рисуется иконками, без текста.
- `OrderTemplate` (`data/orders/`, FTUE — `data/orders/ftue/`): id, required, strength_req, purity_req, base_pay, min_rank, weight (0 — генератор не выдаёт), line_key. База сгенерированных = формула §5.3; у FTUE — своя (§9). Фраза общая для заказов одного рецепта (`ORDER_<РЕЦЕПТ>_LINE`).
- `ClientData` (`data/clients/`): id, name_key, portrait_neutral / happy / upset (пока нет — показывается нейтральный), min_rank, orders, **pay_multiplier** (гонец ×2), **visits_per_day** (гонец 1, 0 — без ограничения).
- `ToolData` (`data/equipment/`): id, kind (station / knowledge / upgrade), price, unlock_rank, name_key, desc_key, icon. Улучшения тоже здесь.
- `RankData` (`data/ranks/`): index, name_key, threshold. **Отклонение:** поля unlocks нет — что открывает ранг, выводится из unlock_rank / min_rank (`DataCatalog.unlocks_for_rank`), чтобы не было двух источников правды.
- `DailyRewardConfig` (`data/daily/`): coins и crystals по дням, crystal_item (Звёздный кристалл), restart_after_last.
- `EconomyConfig` (`data/economy/`): все пороги, скорости и множители из §3, §5, §8, §12 и функции, которые их толкуют (звёзды, извлечение, база, оплата). Числа ввода, подсказок и раскладки из §12 живут в `@export` компонентов (S1.5).
- Ключи текстов: `PROPERTY_<ID>_NAME`, `ING_<ID>_NAME`, `RECIPE_<ID>_NAME/_DESC`, `ORDER_<РЕЦЕПТ>_LINE`, `ORDER_FTUE_<N>_LINE`, `CLIENT_<ID>_NAME`, `TOOL_<ID>_NAME/_DESC`, `RANK_<N>_NAME`. Тексты ru/en — в `localization/strings.csv` (S1.7, прошли humanizer); валидатор проверяет, что каждый `*_key` из данных есть в CSV (L011).
